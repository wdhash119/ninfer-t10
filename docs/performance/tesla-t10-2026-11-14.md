# Tesla T10（SM75）多卡 NInfer prefill 专项优化

日期：2026-11-14  
源码：`/public/src/ninfer-t10`  
基线：`/public/src/ninfer-all`，共同起点 `c0321db023ee1d4ded4afbeaf7404327aadfe640`  
模型：`/public/llm/models/qwen/ninfer-qwen3.8-27b/qwen3.8-27b-ult-unc-q4_k_m-v3.ninfer`

## 结果摘要

在完全相同的双卡 TP、7,680-token NIAH 输入上：

- 原始 FP32-partial/pieces：66.0 tok/s，TTFT 116.30 s。
- 仅关闭 pieces：76.0 tok/s，TTFT 101.01 s。
- 最终 TP-share cuBLAS + 默认关闭 pieces，chunk 4096：**286.8 tok/s，TTFT 26.79 s**。
- 同双卡条件加速 **4.34×**；响应正文与基线一致。
- 四卡最终路径：8K **436.1 tok/s / TTFT 17.62 s**；64K **430.3 tok/s / 149.97 s**；128K **407.0 tok/s / 319.62 s**。

## 根因与修改

### 1. TP rank 没有继承 cuBLAS policy

`src/models/qwen3_5/execution/parameters.cpp` 原先只按整层形状提升 `AllowPrefillCublas`，TP rank 的 output/down 与双父 gate/up 权重仍是 `A16Only`。现在仅在 Turing 且用户显式开启 `--prefill-cublas` 时保留该 policy，实际是否进入路线仍由运行时形状和宽度 gate 决定。

### 2. TP 所需的 FP32 partial 没有 cuBLAS store 路线

TP 的 output/down 与双父 gate/up 通过普通 `linear` 写 FP32 rank partial，而不是 BF16 `linear_add`。新增：

- `w4_cublas_store_fp32_launch()`；
- FP32 store epilogue，保留未舍入的 rank partial，由既有 all-reduce 完成求和与 residual 处理；
- Qwen3.8-27B 的完整/TP2/TP4 gate/up 与 output/down 形状映射；
- 相应 workspace 容量计算。

涉及 `src/ops/linear/linear.cpp`、`src/ops/linear_swiglu/q4cublas/*`。非 Turing 路径不变，默认不开启 cuBLAS 时也不变。

### 3. SM75 默认关闭 prompt pieces

`src/models/qwen3_5/execution/text.cpp` 在 Turing 上默认走整 chunk exchange，其他架构保持原行为。可用以下环境变量恢复上游分片路径做 A/B：

```bash
NINFER_TP_PROMPT_PIECES=1
```

## 正确性与测试

- Release 构建成功，NVCC 13.4.92，SM75。
- `ninfer_w4_cublas_prefill_test` 通过，包括新增 TP2/TP4 Q4/Q5 FP32-partial 与 gate/up 形状；测试检查实际路线命中、workspace 上限、guard bytes 和 FP64 oracle。
- 已测 8K/64K/128K 的响应均为 `ORCHID=493817; COLOR=COBALT`，与基线一致。
- cuBLAS 是既有的精度权衡路线；本轮完成了单元误差和固定响应检查，但没有重新跑完整 perplexity。其质量边界仍按项目 `docs/maintainer/quality-trade-experiments.md` 理解。
- 本轮未覆盖 MTP 开启后的性能、非 Qwen3.8 模型、TP8、非 Q4/Q5 权重。

## 使用命令

```bash
cd /public/src/ninfer-t10
MODEL=/public/llm/models/qwen/ninfer-qwen3.8-27b/qwen3.8-27b-ult-unc-q4_k_m-v3.ninfer

build/apps/ninfer-serve "$MODEL" \
  --devices 0,1,2,3 --tensor-parallel \
  --prefill-cublas --prefill-chunk 4096 \
  --embedding-residency host \
  --max-context 133120 --kv-capacity auto --kv-dtype int8 \
  --max-concurrency 1 --spec none \
  --host 127.0.0.1 --port 18080
```

双卡将 `--devices` 改为 `0,1`。2048 chunk 在双卡 8K 上仅比 4096 慢约 0.9%，需要降低 workspace 或缩小其他 decode lane 的阻塞时间时可使用 2048。

## 构建与测试复现

```bash
cd /public/src/ninfer-t10
export PATH=/usr/local/cuda/bin:$PATH
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_ARCHITECTURES=75 \
  "-DCMAKE_CUDA_FLAGS_RELEASE=-O3 -DNDEBUG" \
  -DBUILD_TESTING=ON
cmake --build build --target ninfer-serve -j12
cmake --build build --target ninfer_tests -j8
build/tests/ninfer_tests ninfer_w4_cublas_prefill_test
```

显式修正 `CMAKE_CUDA_FLAGS_RELEASE` 是因为第一次缺少 NVCC 的配置曾把该缓存留空；当前缓存已修正。不要把无 `-O3 -DNDEBUG` 的对象用于性能比较。
